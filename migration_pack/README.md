# migration_pack — manual DB ops (emergency)

Эта папка **не используется рантаймом** и не нужна для обычного деплоя.
Она нужна как "страховка" для ручного переноса/восстановления Postgres (например, при миграции на новый Neon-проект, когда схему/данные переносили dump/restore и таблица `schema_migrations` потерялась).

## Когда это НЕ нужно
Если база новая/пустая — используйте только стандартный раннер миграций:

```bash
npm i
npm run migrate
```

## Сценарии использования

### A) База уже содержит схему/данные, но `schema_migrations` не настроена
1) (Опционально) привести БД к минимальному инфраструктурному состоянию:

```bash
psql "$DATABASE_URL" -f migration_pack/01_reconcile.sql
```

2) **Только если вы уверены**, что схема реально соответствует текущему набору миграций в `migrations/`:

```bash
psql "$DATABASE_URL" -f migration_pack/00_mark_all_applied.sql
```

> ⚠️ Важно: `00_mark_all_applied.sql` **не выполняет миграции**, он лишь создаёт/заполняет `schema_migrations`.
> Используйте его только когда схема уже приведена в актуальный вид (например, вы переносили базу целиком).

### B) Экстренная проверка после переноса
После выполнения шагов выше запустите:

```bash
node migrations/run.js --dry-run
```

Ожидаемо: все миграции будут `skip`.

## Что внутри
- `01_reconcile.sql` — безопасный (идемпотентный) скрипт: включает минимальные инфраструктурные вещи (pgcrypto/outbox/audit/индексы/soft-delete колонки). Можно запускать повторно.
- `00_mark_all_applied.sql` — создаёт `schema_migrations` и отмечает миграции как применённые (использовать осторожно).
