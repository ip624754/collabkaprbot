# Backoffice Operator Job Map

**Цель:** строить backoffice вокруг работы оператора, а не вокруг таблиц БД.

## 1. Главные jobs

| ID | Job | Вопрос оператора | Текущая поддержка | Gap |
|---|---|---|---|---|
| J-01 | Понять, работает ли система | Что сломалось и что делать первым? | сильная: Обзор + Система | нет единой task queue |
| J-02 | Найти человека | Кто это, что у него есть, где проблема? | очень сильная: Пользователи | нет полной collaboration history |
| J-03 | Разобрать платёж | Применился ли платёж и что получил пользователь? | сильная read-only | нет bounded action workflow в web |
| J-04 | Разобрать коллаборацию | Где застряла заявка/диалог/сделка? | почти отсутствует в web | P1 product gap |
| J-05 | Проверить коммуникацию | Что подготовлено, доставлено, пропущено? | средняя/сильная | delivery detail фрагментирован |
| J-06 | Проверить инвайты | Кто пригласил, что активировалось, почему баллы pending? | Telegram-admin/DB only | web gap |
| J-07 | Проверить розыгрыш | Закончился ли, есть ли winner evidence, claim/publish status? | Telegram-admin/DB only | web gap |
| J-08 | Безопасно изменить состояние | Как сделать действие и не ошибиться? | намеренно Telegram-only | durable audit нужен до расширения writes |
| J-09 | Доказать действие | Кто, когда, что изменил и почему? | Redis recent audit | audit недостаточно долговечен для широких writes |

## 2. Приоритет

### Highest leverage

1. Единая очередь внимания на Обзоре.
2. Collaboration Control Center.
3. Growth/Trust Operations: invites + giveaways + moderation.

### Не приоритет

- новый landing framework;
- пользовательский web-кабинет;
- web-копия Telegram wizard;
- ORM migration;
- React/Next rewrite;
- массовые web mutations.

## 3. Правило каждого экрана

Экран должен отвечать на четыре вопроса:

```text
Что произошло?
Почему это важно?
Какое действие допустимо?
Где evidence / audit trail?
```

Если экран не отвечает хотя бы на три из четырёх вопросов, он не готов к включению в основной backoffice navigation.
