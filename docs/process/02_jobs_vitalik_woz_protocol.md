# 02 — Jobs × Vitalik × Woz — High‑Signal Builder Protocol (для Collabka PR)

> Примечание: держим **один** файл (Windows распаковка не дружит с двумя путями, отличающимися только регистром).

Этот протокол нужен, чтобы работа шла **коммитами**, без регрессий и без «разрастания поверхности».

## 0) Мини‑контекст (что важно именно здесь)
- Runtime: **Vercel serverless** → всё пакетно, без долгих циклов.
- База: **Neon** → бережём CU, **не добавляем лишние DB‑запросы** в меню/кнопки.
- Control plane: cron’ы `/api/cron/*` под **Bearer `CRON_SECRET`**.
- Source of truth по текущему состоянию: `docs/00_CURRENT_STATE.md`.

## 1) Три «голоса»
- **Jobs** — простота и UX без тупиков.
- **Vitalik** — прозрачность: факты, метрики, аудит‑след.
- **Woz** — инженерная аккуратность: атомарность, идемпотентность, минимальная сложность.

## 2) Главный закон
### Никаких «готово» без артефактов
Если сказано «сделано» — значит приложены:
- **FULL zip** (весь проект),
- **Hotfix zip** (только изменённые файлы),
- **git-apply patch**,
- список изменённых файлов + что поменялось,
- QA чеклист.

## 3) Definition of Done (DoD) для каждого микро‑шага
- ✅ маленький, обратимый шаг (или явно указано, что необратимо)
- ✅ не ломаем hot paths (меню/кнопки/хабы)
- ✅ не ухудшаем Neon: без лишних DB‑запросов в UI
- ✅ `node --check` для ключевых файлов
- ✅ smoke‑проверка (минимум 5 шагов)
- ✅ риски + rollback (ENV‑гейт/feature flag/быстрый откат)

## 4) Шаблон ответа ассистента (каждый раз)
### A) Understanding
1–3 строки: что делаем и какие ограничения.

### B) Plan (по коммитам)
`Commit 01…N` — цель + какие файлы/таблицы.

### C) Changes
Список файлов + что меняется (без воды).

### D) QA
short smoke: 5–10 шагов.

### E) Risks / Rollback
Что может сломаться и как откатиться.

### F) Deliverables
Ссылки: FULL zip + Hotfix zip + git-apply patch.

## 5) Анти‑грабли (обязательные гейты)
- никаких массовых regex‑замен
- всё, где возможны дубли (cron / draw / списания) → lock + идемпотентность + транзакции
- cron/webhook защищаем Bearer‑секретом
- рискованные фичи — через ENV‑флаг или runtime toggle

## 6) Мини‑шаблон постановки задачи (копипаст)

```text
Задача: [название]

Цель (Jobs):
- [какой UX/результат]

Контекст:
- файлы/модули/эндпойнты
- роли (brand/creator/mod/admin)

Ограничения (Woz):
- без регрессий
- без лишних DB‑запросов в меню/кнопки
- serverless: пакетно

Прозрачность (Vitalik):
- что логируем/считаем (если надо)

План:
- Commit 01: ...

QA:
- 5–10 шагов smoke

Артефакты:
- FULL zip + Hotfix zip + git-apply patch + files list + QA
```
