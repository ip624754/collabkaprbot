# 01 — Как работать «как senior» в этом проекте (процесс без регрессий)

Этот файл — про **дисциплину разработки**, чтобы изменения были:
- маленькие и обратимые,
- проверяемые,
- без регрессий в проде,
- без лишней нагрузки на Neon.

## 1) Никаких «готово» без артефактов
Если в ответе говорится «сделано / выдал / готово» — значит в ответе **есть файлы**:
- **FULL zip** (весь репозиторий со всеми изменениями),
- **Hotfix zip** (только изменённые файлы),
- **git-apply patch**,
- список изменённых файлов + что поменялось,
- QA чеклист.

Если файла нет — считаем, что не готово.

## 2) DoD (Definition of Done) для каждого микро‑шага
Микро‑шаг считается завершённым только если:
- ✅ изменения **минимальные** (small surface area),
- ✅ нет регрессий в горячих UI путях (меню/кнопки/хабы),
- ✅ **не добавили лишних DB‑запросов** в рендер меню/кнопок,
- ✅ `node --check` проходит хотя бы для ключевых файлов (`src/bot/bot.js`, `src/bot/cron.js`),
- ✅ smoke‑путь описан (в `smoke-tests_short.md` либо отдельным чеклистом),
- ✅ указаны риски + план отката (feature flag / ENV‑гейт).

## 3) Анти‑грабли (гейты)
- **Не делаем массовые regex‑замены**: только точечные правки.
- Всё, что может дать дубли/двойное списание/двойной draw:
  - идемпотентность,
  - атомарность (транзакции),
  - locks (Redis + при необходимости PG advisory lock).
- Cron/webhook всегда защищены:
  - `Authorization: Bearer <CRON_SECRET>`
  - POST‑only где нужно.
- Любая рискованная фича — через переключатель:
  - ENV flag или runtime toggle (Redis).

## 4) Как ставить задачи, чтобы не «поплыло»
В одном сообщении:
1) **Scope**: что делаем (1–3 пункта) и чего НЕ делаем.
2) **DoD**: какие проверки обязательны.
3) **Риски**: что нельзя сломать (cron, payments, broadcast, /start gate).

## 5) Мини‑шаблон задачи (копипаст)

```text
Задача: [название]

Цель:
- [что пользователь увидит/сделает]

Контекст:
- где в коде (файлы/модули/эндпойнты)

Ограничения:
- не ломать прод, без лишних DB в меню/кнопках
- serverless: пакетно, без длинных циклов

План (по коммитам):
- Commit 01: ...

QA:
- шаги smoke (5–10)

Артефакты:
- FULL zip + Hotfix zip + git-apply patch + files list + QA
```
