# 09 — Admin UX Standard (Collabka PR)

Цель: сделать админку "пультом" — быстро, предсказуемо, без лишних кнопок и без регрессий.

Этот документ — правило для **всех** новых админ‑экранов и правок существующих.

---

## 1) Навигация (футер)

### 1.1. Базовый футер для админ‑экранов
На **каждом** админ‑экране (любой экран, который доступен из `👑 Админка`) внизу должен быть единый футер:

1) **возврат в раздел админки** (одна кнопка):
- `⬅️ Операции` → `a:admin_ops`
- `⬅️ Коммуникации` → `a:admin_comms`
- `⬅️ Система` → `a:admin_sys`
- `⬅️ Админка` → `a:admin_home` (только для самых верхних админ‑экранов)

2) **escape‑ряд** (всегда):
- `📋 Меню` → `a:menu`
- `🏠 Home` → `a:home`

> Почему так: админ никогда не должен “застревать” в глубине флоу.

### 1.2. Локальный back (контекст)
Если экран имеет явный контекст (список/карточка/детали), добавляем **локальный back** *выше футера*:
- `⬅️ К списку` → назад в список
- `⬅️ К карточке` → назад в карточку
- `⬅️ Назад` → назад в предыдущий шаг мастера

Локальный back **не заменяет** базовый админ‑футер.

---

## 2) Имена разделов и кнопок (фиксируем)

### 2.1. Разделы админки
- `🧰 Операции` — users/payments/broadcast/audit/metrics
- `💬 Коммуникации` — system notice / DM templates / outbox / official queue
- `⚙️ Система` — тумблеры, QStash статус, модераторы, подарки, Founder

### 2.2. Коммуникации
- Для админа: `📣 Объявление` (это **system notice**, баннер без рассылки)
- Для пользователя: `📣 Актуальное объявление` (показ по запросу, даже если already seen)

### 2.3. Сообщение пользователю (admin DM)
В пользовательском сообщении используем фиксированный стиль:
- Заголовок: `📣 Сообщение от администрации Collabka PR`
- CTA‑кнопки: `📋 Открыть меню`, `💬 Поддержка`, `✅ Понятно`

---

## 3) Лэйаут клавиатуры

- **Обычно**: максимум **2 кнопки в ряд**.
- Исключение: пагинация (`⬅️  1/5  ➡️`) — 3 в ряд.
- Сначала — основные действия (mutating), затем второстепенные (просмотр/вставка/справка).
- Деструктивные действия (удалить/очистить/стоп) требуют явного подтверждения.

---

## 4) Рендер и производительность

- В горячих админ‑списках не добавлять новые DB‑чтения “на рендер” без сильной причины.
- Любые тяжёлые действия — только по клику.
- Redis‑degraded режим: админ‑UX не должен ломать основной прод‑UX.

---

## 5) Контроль регрессий

- После любой правки админ‑клавиатур прогоняем: `npm run lint:nav`.
- Если экран намеренно без `📋 Меню`/`🏠 Home`, это должно быть очень осознанно и помечено `navlint: ignore` (крайний случай).
