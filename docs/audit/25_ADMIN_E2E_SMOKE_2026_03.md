# 25 — Admin E2E smoke — 2026-03-03

Цель: быстрый end‑to‑end smoke по ключевым экранам 👑 Админки, чтобы после деплоя за 10–12 минут поймать регрессии в:
- Users
- Payments
- Outbox
- System
- Broadcast

> Важно: этот smoke проверяет UX‑предсказуемость (Back/Menu/Home), отсутствие “залипаний” input‑mode (expectText) и базовую работоспособность админских действий.

---

## Предусловия

- Вы — **super‑admin** (ваш id в `ADMIN_IDS`).
- Бот доступен (prod/staging), `/api/health` отдаёт `ok=true`.
- Проверки “Outbox privacy” делайте **в группе** (не DM), чтобы убедиться, что приватность работает.

---

## Сценарий A — Users (поиск → карточка → заметка → сообщение)

1) Открыть `👑 Админка → 👥 Пользователи`.

Ожидаем:
- список/пагинация открываются без ошибок;
- есть предсказуемая навигация (возврат/меню/home).

2) Нажать `🔎 Поиск` и отправить текст поиска (username или id).

Ожидаем:
- найденные пользователи отображаются;
- **важно:** нажать `📋 Меню` или `🏠 Home`, затем написать любой текст — он **не должен** улетать в поиск (input‑mode должен быть снят).

3) Открыть карточку пользователя.

Ожидаем:
- есть кнопки “Назад” в Users, `📋 Меню`, `🏠 Home`;
- карточка не падает при отсутствующих полях.

4) Зайти в `📝 Заметка` (admin note), ввести короткий текст, сохранить.

Ожидаем:
- после сохранения возвращает в карточку (или даёт явный next‑step);
- `❌ Отмена`/`📋 Меню`/`🏠 Home` не оставляют input‑mode “залипшим”.

5) (Опционально) `✉️ Написать` пользователю → отправить короткое тест‑сообщение.

Ожидаем:
- сообщение уходит;
- квитанция в админке самодостаточная и есть навигация назад/меню/home.

---

## Сценарий B — Payments (список → просмотр → ручной apply)

1) Открыть `👑 Админка → 💳 Платежи`.

Ожидаем:
- список открывается;
- переход в платеж/квитанцию работает.

2) Открыть любой платеж (или тестовый), зайти в `👁 Просмотр`.

Ожидаем:
- видны ключевые поля;
- кнопки назад/меню/home работают.

3) Если есть тестовый платеж, который можно “применить” (manual apply) — выполнить apply.

Ожидаем:
- apply даёт понятный результат (успех/уже применён/нельзя применить);
- повторный apply не приводит к дублю (exactly‑once поведение).

---

## Сценарий C — Outbox (privacy + repeat)

1) В **группе** (не в личке) открыть `👑 Админка → 📤 Outbox`.

Ожидаем:
- сниппеты текста скрыты (🔒) и повторная отправка отключена/неактивна;
- нет утечек приватного текста в группе.

2) В **личке с ботом** открыть `👑 Админка → 📤 Outbox`.

Ожидаем:
- сниппеты видны;
- открыть запись → `✉️ Повторить` работает (с предпросмотром), навигация остаётся предсказуемой.

---

## Сценарий D — System (QStash status / ping)

1) Открыть `👑 Админка → ⚙️ Система`.
2) Перейти в `🛰 QStash статус`.

Ожидаем:
- экран статуса открывается;
- кнопка “назад” возвращает в систему/админку;
- `📋 Меню` уводит в пользовательское меню.

3) (Опционально) `🧪 Send signed ping`.

Ожидаем:
- приходит результат (ok/ошибка) без зависаний.

---

## Сценарий E — Broadcast (start → cancel → create)

1) Открыть `👑 Админка → 📣 Рассылки`.
2) Нажать `➕ Новая рассылка`.

Ожидаем:
- появляется экран “Отправь 1 сообщение…”;
- `❌ Отмена` реально отменяет и снимает input‑mode.

3) Проверка “не залипает”:
- нажать `❌ Отмена`, затем написать любой текст — он **не должен** восприниматься как контент рассылки.

4) Снова зайти в `➕ Новая рассылка`, отправить **текст**.

Ожидаем:
- контент принят и можно перейти к кнопкам/превью/подтверждению;
- финальные экраны самодостаточные, без “пустых сообщений без кнопок”.

---

## Что фиксировать, если что-то не так

- Точный экран/кнопка (action key), после которой поведение стало странным.
- Был ли активен input‑mode (бот “ждал текст”), и получилось ли выйти через `❌ Отмена` / `📋 Меню` / `🏠 Home`.
- Для Broadcast: скрин финального экрана и список кнопок.
