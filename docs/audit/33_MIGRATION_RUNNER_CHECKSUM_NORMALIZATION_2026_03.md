# STEP304 — Migration runner: checksum normalization (LF + trimEnd)

Контекст (из NotebookLM audit):
- Текущий механизм checksum в `migrations/run.js` хэшировал SQL «как есть». Любое изменение окончания строк (CRLF↔LF) или незначимые изменения в конце файла (например, добавили/убрали финальный перевод строки) приводят к `Checksum mismatch`.
- В результате деплой/префлайт может падать, хотя миграции по смыслу не менялись.

Риск:
- Ложные падения в прод-цепочке деплоя из-за особенностей редактора/OS.
- Повышенная вероятность “ручных фикс-обходов”, что опасно для дисциплины миграций.

Решение:
- Ввести **нормализацию SQL перед checksum**:
  - EOL приводим к LF (`\r\n`/`\r` → `\n`)
  - `trimEnd()` только на конце файла
- Сохранить fail-closed на любые реальные изменения содержимого миграции.
- Добавить **backward compatibility**: раннер принимает ранее записанные checksum значения (legacy raw/lf/crlf) и типовые варианты «final newline», чтобы обновление раннера не требовало переписывать `schema_migrations`.
- Генератор `scripts/gen-mark-all-applied.js` синхронизирован: теперь тоже пишет checksum по нормализованному SQL.

Заметка:
- Мы по-прежнему не редактируем старые миграции. Нормализация нужна только чтобы не падать на whitespace-only дрейфе между окружениями.
