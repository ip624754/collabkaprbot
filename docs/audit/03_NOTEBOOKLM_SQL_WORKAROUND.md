# NotebookLM не принимает .sql — что делать

Некоторые загрузки в NotebookLM блокируют файлы с расширением `.sql`.
Чтобы аудит всё равно был полноценным, используем **текстовые копии SQL**.

## Вариант 1 (самый простой): загрузить txt-версии

Вместо:
- `migrations/*.sql`
- `migration_pack/*.sql`

загружаем:
- `migrations_txt/*.sql.txt`
- `migration_pack_txt/*.sql.txt`

Это те же файлы, просто в формате, который NotebookLM принимает.

## Вариант 2: сгенерировать папку txt-версий локально

Запусти в корне репозитория:

```bash
npm run gen:notebooklm-sources
```

Команда создаст папку `dist/notebooklm_sources/` с:
- `docs/` (ключевые доки)
- `migrations_txt/` (копии миграций)
- `migration_pack_txt/` (копии pack-скриптов)
- `NEON_HISTORY/` (контекст по переезду)

Дальше эту папку можно:
- зазиповать и загрузить целиком, или
- загрузить выборочно по папкам.

## Важно

Текстовые копии нужны **только** для удобной загрузки в NotebookLM.
Реальные миграции применяются строго из `migrations/*.sql` через `migrations/run.js`.
