# 19 — STEP287: Preflight Node syntax check (node --check) — 2026-03-03

## Контекст
На STEP285/286 поймали реальную прод‑регрессию: Vercel падал на cold start с `SyntaxError: Invalid or unexpected token`.
Причина была тривиальная (literal newline внутри строки `'...'`), но ловится только на стадии компиляции JS‑модуля.

## Цель
Сделать так, чтобы подобные ошибки **ловились до деплоя** одной командой `npm run preflight`.

## Изменение
- `scripts/preflight.js` теперь дополнительно прогоняет `node --check` по ключевым entrypoint‑ам проекта.
- Если в репо есть `api/qstash/`, то автоматически проверяются все `api/qstash/*.js`.

## Почему это безопасно
- Preflight — dev‑инструмент. Он не меняет runtime‑логику и не влияет на прод.
- Проверка `node --check` дешёвая и быстро валит пайплайн при синтаксической ошибке.

## QA
1) Локально:
   - `npm run preflight` проходит.
2) Негативный тест (опционально):
   - искусственно сломать синтаксис в одном файле (например, добавить лишнюю кавычку), убедиться что `npm run preflight` падает на шаге `node --check`.
