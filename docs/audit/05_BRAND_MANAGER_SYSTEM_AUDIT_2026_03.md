# Brand Manager system audit (2026-03) — STEP273

Цель: один раз системно проверить “бренд ↔ менеджер бренда” и убрать UX‑шум/регрессии.

## Что проверено

1) **Роли и поверхности UI**
- Creator меню (`mainMenuCreatorKb`) — наличие/отсутствие brand-only действий.
- Brand меню (`mainMenuBrandKb`) — отличие владельца бренда и менеджера бренда.
- Home hub (`renderHomeHub`) — переключение режимов.

2) **Brand Team (владельцы бренда)**
- Гейт “👔 Менеджеры бренда” (`a:brand_team`) — unlock после заполнения профиля + Brand Plan/Brand Pass.
- Приглашение менеджера (`a:bm_invite`), добавление по `@username` (`a:bm_add_username`), список/удаление (`a:bm_list`, `a:bm_rm_*`).

3) **Manager mode (команда бренда)**
- Вход в кабинет (`a:bm_home`) → выбор бренда (если несколько) → Brand Inbox.
- Переключение бренда (`a:bm_pick_brand` / `a:bm_set_brand`).
- Ограничения менеджера: отсутствие доступа к профилю бренда и оплатам/подписке.

4) **Безопасность**
- Менеджер не может открыть owner-only разделы (профиль бренда, план) через старые кнопки/прямые callback keys — проверяется в обработчиках `a:brand_profile`, `a:brand_profile_edit`, `a:brand_plan` (deny, если bm.enabled и bm.brandUserId != u.id).

## Найденные косяки (до STEP273)

### 1) Лишние DB‑запросы в горячих путях меню/хаба
- `renderMainMenu` делал `db.listBrandsForManager(u.id)` ради показа кнопки “🧑‍💼 Я менеджер бренда”.
- `renderHomeHub` делал DB‑lookup списка брендов ради подсказки “активный бренд”.

Почему это плохо:
- Нарушает принцип “hot UI DB‑reads — нет” (Neon/CU), увеличивает риск деградаций.

### 2) UX‑шум: «Доступ менеджера отозван»
Одинаковая формулировка показывалась и тем, кого **никогда не добавляли**, и тем, кого реально удалили.

Почему это плохо:
- Путает, вызывает лишние вопросы/поддержку.

## Исправления (STEP273)

1) **Кнопка “🧑‍💼 Я менеджер бренда” всегда видна**, но доступ проверяется **на клике** внутри manager flow (`a:bm_home`).
- Меню больше не делает DB‑проверок “canManager”.

2) **Home hub стал DB‑light**
- Убран DB‑lookup брендов менеджера из рендера Home.
- Переключение в менеджерский режим проверяет доступ на клике `a:home_mode|m:brand_manager` (DB‑проверка допустима там).

3) **Единый гейт‑текст для отсутствия доступа**
- Введён helper `bmNoAccessHtml()` и заменены разрозненные “отозван” сообщения.

## Smoke checklist
- Любой юзер → 📋 Меню: видит “🧑‍💼 Я менеджер бренда”.
- Юзер без доступа → нажать → видит понятный гейт (не “отозван” в одиночку).
- Реальный менеджер → нажать → (если брендов несколько) пикер бренда → Brand Inbox.
- Менеджер → попытаться открыть `🏷 Профиль бренда` / `⭐ Brand Plan` из старых сообщений → deny “только владельцу бренда”.
