# 22 — Admin UX sweep (input-mode escape hatch) — 2026-03-03

Цель: убрать «залипание» режима ввода (expectText) в админке и сделать выходы из любого input‑экрана предсказуемыми.

## Контекст

В админских сценариях много шагов, где бот ждёт текст/ввод:
- поиск пользователей
- заметка админа
- шаблоны/сообщения
- служебные поля в системных экранах

Если админ нажимает `📋 Меню` или `🏠 Home`, он ожидает, что режим ввода будет **сброшен**, иначе следующий текст может «улететь» не туда.

## Что сделали

1) **Escape hatch для input-mode**
- `📋 Меню` и `🏠 Home` делают best‑effort сброс `expectText` перед рендером.
- Это убирает класс багов: «нажал Меню, но бот всё ещё ждёт текст».

2) **Входы в ключевые админ‑разделы очищают ожидание ввода**
- При переходах в важные админские разделы (Users/Payments/Outbox/System/Notice) выполняется best‑effort сброс `expectText`, чтобы не переносить input‑режим между разделами.

3) **Заметка админа: предсказуемая навигация**
- На экране ввода заметки добавлен нормальный back‑путь и стандартная админ‑навигация (`⬅️ ...` + `📋 Меню` + `🏠 Home`).

## QA (быстро)

- Открыть любой input‑экран в админке (например поиск пользователя) → нажать `📋 Меню` → отправить обычный текст в чат.
  Ожидаем: текст **не** должен обрабатываться как продолжение старого ввода.

- То же для `🏠 Home`.

- Перейти из input‑экрана в другой админ‑раздел (Users → Payments или Outbox) и убедиться, что input‑режим не «переносится».

Риск регрессий: **низкий** (это только очистка input‑состояния и UX‑навигация; бизнес‑логика не меняется).
