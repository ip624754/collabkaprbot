# 26 — callback_data hardening (Telegram 64 bytes) — 2026-03-04

Цель: убрать риск “тихих кнопок” из‑за ограничения Telegram `callback_data <= 64 bytes`.

## Что могло ломаться
- **Brand Manager**: `a:bm_set_brand|...|ret:brand_deals|...` при длинных ID выходил за 64 байта → Telegram мог не показать кнопку.
- **Curator audit**: `a:cur_audit|...|pg:...|ret:...` на грани лимита при росте ID → бомба замедленного действия.
- **Brand filters**: `a:bx_fset`/`a:bx_fpick` содержали дублирующий `p` (равный `pg`) → лишние байты.

## Что сделано
- Добавлены компактные callbacks (с обратной совместимостью):
  - `a:bms` — Brand Manager set brand (вместо тяжёлого `a:bm_set_brand`).
  - `a:ca` — Curator audit (вместо `a:cur_audit`).
- Для Brand Manager return-коды сделаны компактными: `brand_deals → bd`, `brand_apps → ba`.
- В Brand filters убрано дублирование `pg`/`p` в callback_data.
- В админских handlers исправлен паттерн двойного `answerCallbackQuery()` (сообщение “Нет доступа.” теперь не теряется).

## QA (ручной)
1) Brand Manager:
- Открыть выбор бренда → убедиться, что кнопки брендов отображаются.
- Нажать на бренд при `ret=brand_deals` (или `brand_apps`) → переход работает.

2) Curator audit:
- Открыть `📜 Журнал` → переключить “Все роли/Только кураторы”, пролистать страницы.
- Кнопки должны отображаться и нажиматься, без “пропаданий”.

3) Brand filters:
- Открыть picker категории/типа/оплаты → пролистать → выбрать значение 10+ символов.
- Кнопки должны быть кликабельны (callback_data не переполняется).

4) Admin deny:
- (На staging) попытаться вызвать admin callback не-админом → увидеть “Нет доступа.”

## Заметка
Telegram может **молча** не показать кнопку при переполнении callback_data, без ошибок в логах. Поэтому любые новые callbacks делаем компактными и проверяем на “длинных” ID.
