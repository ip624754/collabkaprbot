# 17 — Workspace Folders: Editors UI disabled by default — 2026-03

## Контекст
В блоке `📁 Папки` существовала опция `👥 Editors` (folder-editor) — делегирование управления папками отдельным людям.
На практике это создаёт лишние вопросы/когнитивную нагрузку и добавляет DB-чтение в горячий рендер меню.

## Решение (без регрессий)
- Функция Editors сделана **опциональной** и **выключена по умолчанию**.
- Включение — только через ENV: `WORKSPACE_EDITORS_ENABLED=1`.

## Что меняется для прод‑пользователя
- В `📁 Папки` больше не показывается кнопка `👥 Editors` (если ENV не включён).
- Папками управляет **owner**.
- Старые кнопки/ссылки на Editors (если где-то сохранились) возвращают «Отключено.» и не создают invite‑токены.

## Технические детали
- В `getRoleFlags` убрана лишняя DB‑проверка `hasAnyWorkspaceEditorRole` из рендера меню (если ENV выключен).
- В `getFolderAccess` запрещён доступ editor‑пользователям (если ENV выключен).

## QA / Smoke
1) Owner → Workspace → `📁 Папки`.
   - Ожидаемо: нет кнопки `👥 Editors`.
2) Все операции папок owner работают как раньше (создать/добавить/удалить/экспорт).
3) Если нажать старую кнопку `👥 Editors` (из истории сообщений):
   - Ожидаемо: callback «Отключено.» или экран «Функция отключена…», без выдачи invite.
